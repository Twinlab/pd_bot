    Внутренний API личного кабинета PD Room¶

    API реализован в cogs/portal_api.py и utils/portal/api.py. Он работает внутри единственного процесса бота, использует текущие менеджеры профиля и тот же FunCog.quotes, который обслуживает Discord. Сайт не получает доступ к SQLite, индексу цитат, Discord bot token или Docker socket. Добавление кода не включает listener и само по себе не является развёртыванием.

    Настройка¶

    Блок portal_api в BotSettings выключен по умолчанию. Переменные окружения:

    Переменная Значение по умолчанию Назначение
    PORTAL_API__ENABLED false Явно включает listener
    PORTAL_API__HOST 127.0.0.1 Адрес только для доверенного backend
    PORTAL_API__PORT 8091 Внутренний порт
    PORTAL_API__TOKEN отсутствует Служебный токен через SecretStr
    PORTAL_API__TOKEN_FILE отсутствует Альтернативный файл токена
    PORTAL_API__MAX_CONCURRENT 4 Одновременные запросы
    PORTAL_API__REQUEST_TIMEOUT 10 Таймаут запроса, секунды
    PORTAL_API__MEMBER_CACHE_SECONDS 15 Положительный кэш членства, до 30 секунд
    PORTAL_API__MEMBER_CACHE_SIZE 512 Ограничение кэша участников и лимитов
    PORTAL_API__REQUESTS_PER_MINUTE 240 Общий лимит запросов
    PORTAL_API__USER_REQUESTS_PER_MINUTE 90 Лимит одного Discord ID

    Нужны настроенный GUILD_ID и ровно один источник токена: 32–512 печатных ASCII-символов без пробелов. Файл читается с пределом 1024 байта, завершающий перевод строки допускается. Токен загружается при запуске кога; смена требует его перезапуска. В журнал не пишутся токен, заголовки или тексты внешних исключений; access log listener выключен. Обычный .env не редактируется как часть разработки API.

    В контейнере loopback доступен только самому контейнеру. Для двух контейнеров нужно отдельно согласовать общую закрытую сеть, bind и передачу одного секрета. Порт нельзя публиковать в интернет или проксировать напрямую из браузера. Production Compose включает listener на 8091, монтирует read-only каталог /etc/pdroom/portal-bot (root:GID 1000, 0750; файл token 0640) и подключает внешнюю Docker-сеть pdroom_portal с alias pd-bot-api. Сеть создаётся с --internal до первого запуска; другие сервисы бота в неё не входят. Для сайта тот же служебный секрет хранится в отдельном каталоге с GID 10001.

    Доверие и авторизация¶

    Каждый запрос требует Authorization: Bearer <service-token> и X-PDRoom-User-ID: <discord-id>. Backend сайта берёт ID только из собственной проверенной Discord-сессии; значения браузера не доверены. Служебный токен даёт backend право представлять участников, поэтому его нельзя отдавать фронтенду.

    API сначала проверяет токен, формат ID, лимиты и готовность Gateway, затем членство в единственном сервере через guild.fetch_member. GET допускает короткий положительный кэш; события выхода/обновления сбрасывают его. DELETE всегда запрашивает участника заново. Ошибка Discord, отсутствие guild в кэше или отключение Gateway означают временную недоступность, а не отсутствие прав.

    Личные данные не кэшируются браузером: все ответы содержат Cache-Control: private, no-store. Неизвестные и повторённые query-параметры, некорректные ID и тела запросов отклоняются. Все Discord ID передаются строками, чтобы JavaScript не терял точность.

    Контракт v1¶

    Метод и путь Параметры Результат
    GET /internal/v1/status нет {ready: true, is_owner: boolean}
    GET /internal/v1/profile period=month\|year\|all, по умолчанию month Личный профиль
    GET /internal/v1/quotes scope=mine\|all, sort=newest\|oldest, offset=0, limit=24 Страница галереи
    GET /internal/v1/quotes/{id}/image нет image/webp
    DELETE /internal/v1/quotes/{id} нет {deleted: boolean}

    Профиль содержит только:

    • user: id, username, display_name, avatar_url, joined_at, is_owner;
    • period: строку month, year или all; месяц и год определяются по Москве;
    • stats: messages, voice_seconds, reactions, games (name, seconds);
    • accounts: dota и faceit, в каждом элементе id и name;
    • data_since: дату начала сбора данных или null.

    Рейтинги, места, «моменты» с текстом сообщений и статистика других людей не включаются. Списки игр и каждой группы аккаунтов ограничены 100 элементами, имена — 256 символами. FACEIT ID является строкой UUID, а не Discord snowflake.

    Галерея возвращает items, total, next_offset (либо null). Элемент содержит id, author_name, created_at, saved_at, saved_by, is_mine, can_delete, jump_url. limit допускает 1–100, offset — 0–100000; сортировка идёт по дате сохранения, затем ID сообщения. Текст цитаты не хранится в индексе. Старые изображения assets/quotes не входят в кабинет.

    scope=mine показывает карточки, сохранённые текущим участником (saved_by). scope=all доступен только владельцу Discord-сервера (guild.owner_id). Источник каждой карточки должен оставаться общедоступным и без NSFW; фильтр выполняется до подсчёта и пагинации, а также перед выдачей картинки и удалением. Картинка имеет дополнительный предел 8 МиБ; текущий предел хранилища — 256 КиБ.

    Удалять может создатель карточки или владелец сервера. Автор исходной фразы и manage_messages сами по себе не дают такого права. Discord-кнопка и API используют одну политику и одну блокировку записи. Перед записью повторно читаются метаданные и текущий владелец сервера. Повторный DELETE уже отсутствующей карточки возвращает {deleted: false}. Удаление убирает карточку из коллекции; исходное сообщение и ранее опубликованные Discord-копии не удаляются.

    Ошибки и восстановление¶

    Ошибка имеет вид {"error": "code"}:

    HTTP Код Значение
    400 invalid_request Некорректные параметры или заголовки
    401 unauthorized Нет правильного служебного токена
    403 member_required Discord подтвердил отсутствие участника
    403 forbidden Нет права на коллекцию или карточку
    404 quote_not_found Нет карточки или её источник закрыт
    429 rate_limited Лимит частоты/параллелизма, Retry-After: 60
    503 bot_unavailable Бот, Discord, ког или хранилище недоступны

    Backend сайта должен преобразовать служебную 401 в ошибку подключения и не выдавать пользователю токен или внутренний адрес. При 503 нельзя подменять реальную ошибку пустым профилем или успешным удалением. После таймаута DELETE нужно перечитать галерею: атомарная операция хранилища могла завершиться, пока HTTP-запрос ожидал ответ. Повторный DELETE идемпотентен.

    Локальные проверки: tests/test_utils/test_portal_api.py, tests/test_cogs/test_portal_api_cog.py, существующие тесты quote service и lifecycle. Они используют локальный aiohttp test server и подменённый Discord, не запускают настоящего бота, не открывают prod-БД и не подтверждают deployment.
