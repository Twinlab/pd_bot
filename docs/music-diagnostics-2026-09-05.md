В REST-параметре `withClient` используются внутренние идентификаторы. Они отличаются от YAML:

| YAML | `withClient` |
|---|---|
| `TV` | `TVHTML5` |
| `WEBEMBEDDED` | `WEB_EMBEDDED_PLAYER` |
| `MUSIC` | `WEB_REMIX`, только поиск |

Запрос с `withClient=TV` не тестирует OAuth-клиент и может вернуть вводящую в заблуждение ошибку отсутствия форматов.

## Причина отказа TV и кандидат исправления

На момент диагностики последний опубликованный релиз — `1.18.2` от 27 июля 2026. Он использует старый Cobalt User-Agent. В [upstream-коммите `b33460b`](https://github.com/lavalink-devs/youtube-source/commit/b33460b38ad13b5cd07da75e46444397cf0ea2df) от 19 августа документировано отклонение этого User-Agent YouTube и замена на PlayStation 4. Наблюдаемая на VM ошибка совпадает с описанием исправления.

Кандидат для испытаний — официальный коммит `f45bbb7aebfcbc1c553769e04af6cd43afa8b7c3`. Он включает исправление TV, обновления Android/iOS и [исправление длины потока без `contentLength`](https://github.com/lavalink-devs/youtube-source/commit/f45bbb7aebfcbc1c553769e04af6cd43afa8b7c3).

Артефакт находится в Maven snapshots, но версия plugin-модуля не содержит суффикс `-SNAPSHOT`:

```yaml
dependency: "dev.lavalink.youtube:youtube-plugin:f45bbb7aebfcbc1c553769e04af6cd43afa8b7c3"
repository: "https://maven.lavalink.dev/snapshots"
snapshot: true
```

Проверенные SHA-256:

```text
1.18.2: fc1128b606b54fda124b78d261c3878198116028baf00f7bd014f44bab95d77d
f45bbb7: b0525dbc04d7d6204877dff299bc3cf087aaf5a2909c2186b18b7bf0662789c5
```

Обе суммы совпали с опубликованными Maven-файлами `.sha256`. В JAR нет добавленных или удалённых файлов; изменены классы Android/iOS/TV, YoutubeAudioTrack с вложенными классами и два файла версии. Исходный diff от `1.18.2` содержит четыре коммита и четыре Java-файла. Это проверка происхождения и объёма изменений, а не доказательство отсутствия всех рисков.

## Изменения в боте

Обычный текст направляется в `ytsearch:`. Явные `ytmsearch:`, `scsearch:`, `spsearch:` и другие поисковые префиксы передаются без дублирования. Ранее Wavelink добавлял к ним свой префикс `ytmsearch:`. Поиск YouTube Music остаётся доступен явно.

Регрессионные тесты проверяют конечный идентификатор Lavalink через настоящий `Playable.search`, включая прямую ссылку, пробелы и обычное название с двоеточием.

В `lavalink/application.yml` закреплена проверенная сборка `f45bbb7`. Для выпуска требуется применить этот YAML на VM и перезапустить Lavalink: Watchtower обновляет образ бота, но не смонтированный конфиг плагинов. Перед обновлением сохраняются исходный YAML и JAR `1.18.2` для отката.

Проверки перед выпуском: весь набор из 1196 тестов прошёл, Ruff check и format check для проекта прошли. Отдельно прошли 49 музыкальных тестов и mypy для `cogs/music.py`.

## Проверка исправленной сборки

В отдельном диагностическом контейнере использованы те же OAuth, прокси, список клиентов и Lavalink `4.2.2`. Изменена только версия YouTube-плагина; `/v4/info` подтвердил загрузку `f45bbb7aebfcbc1c553769e04af6cd43afa8b7c3`. Новый JAR на VM совпал с заранее проверенным SHA-256.

Все семь ранее отказавших записей получили HTTP 200 и первые 65 536 байт потока за 0,47–0,84 с. Контрольная проба `dQw4w9WgXcQ` с `withClient=TVHTML5` также успешна: HTTP 200 за 1,14 с вместо ошибки `The page needs to be reloaded`. Формат этих потоков — `video/mp4`; получение первых байт не заменяет проверку полного декодирования и воспроизведения в Discord.

Отдельная Java-проба полного декодирования была остановлена во время сетевого ожидания и не подтвердила воспроизведение. Окончательная проверка выпуска — обычный `/play` в Discord с контролем событий плеера и слышимости у слушателя.
