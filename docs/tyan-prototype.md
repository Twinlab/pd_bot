# /tyan: генератор и редактура

В код подключены команда Discord, три YAML-словаря, карточка и сохранение
дневной выдачи в SQLite. Локальные проверки используют отдельную временную БД.
Выпуск на VM выполняется по [плану миграции](tyan-migration-plan.md).

## Предпросмотр

Из корня проекта в PowerShell:

```powershell
.venv/Scripts/python.exe -X utf8 -m utils.tyan.preview
.venv/Scripts/python.exe -X utf8 -m utils.tyan.preview --seed 20260910 --output docs/tyan-preview.md
```

Это 22 обычные случайные выдачи, затем 6 принудительно положительных
и 2 отдельно включённых микроивента. Последние восемь показывают возможности
генератора; их доля не отражает реальные вероятности.

## Поведение

Возраст 18–80, рост 140–200 и вес 30–120 выбираются равномерно и независимо.
Нелепые сочетания чисел намеренно не исправляются.

Обычная выдача имеет 1–3 текстовых элемента: типаж обязателен, прилагательное
и особенность необязательны. Веса числа элементов: 20/50/30.
Отдельный шанс 20% создаёт сочетание с положительным прилагательным и
неотрицательным типажом. Положительная особенность добавляется только при
выборе трёх элементов; удачный образ может быть коротким.
Метка положительности относится к тексту, не гарантирует обычные рост/вес.

Словари лежат в `utils/tyan/content/`. В каждой записи стабильный ID,
текст, редакторская окраска, семейство близких слов и необязательный вес.
Положительные/нейтральные/отрицательные метки служат подбору вымышленных
сочетаний. При изменении формулировки ID сохраняется; для новой сущности
создаётся новый ID. Обновления словаря применяются после перезапуска.

Один результат за московский день, включая микроивенты. Генератор возвращает
готовый снимок из переданной истории, поэтому изменение словаря не меняет
уже выданный текст. Discord-команда получает историю через `TyanDataManager`
из SQLite; утилита предпросмотра передаёт её в памяти.

Защита от повторов использует персональные сроки: 30 дней для прилагательного,
60 для типажа, 90 для особенности. Типаж по возможности не повторяется на сервере
в тот же день; пары типаж/прилагательное и типаж/особенность избегаются 120 дней.
Недавние элементы и семейства имеют пониженный вес. Если редакторский словарь
исчерпан, ограничения слов поэтапно ослабляются. Дневная стабильность и перерыв
событий не ослабляются. Небольшой пробный словарь не гарантирует все сроки
для любого количества пользователей.

## Микроивенты

Вместо обычной строки появляется одно из двух сообщений:

- `тебе досталась мать @random-user`
- `тянки не досталось. сегодня дрочишь`

Шанс каждого — 0,5% на новую дневную выдачу, когда истёк общий перерыв.
После любого события оба блокируются на 14 полных суток на весь сервер.
При 15 новых выдачах в день это примерно одно событие раз в 21 день
в долгосрочном среднем, с возможными более длинными паузами.
0,1% без перерыва означало бы примерно 67 дней ожидания каждого события.

Цель для первого события выбирается среди переданных ID реальных участников,
кроме автора. При отсутствии другого участника вместо него генерируется
обычная тянка. Discord-обработчик передаёт участников текущего сервера
из кеша Discord и исключает ботов. Member intent уже включён в настройках бота.
В предпросмотре ID заменён подписью `@random-user`.

Первая версия содержит 338 элементов: 95 прилагательных, 140 типажей,
103 особенности. Это одобренный набор; его можно расширять без изменения
схемы БД. При исчерпании совместимых вариантов мягкие антиповторы ослабляются.


## Редакторский ориентир

Смешиваются узнаваемые типажи и короткие характеристики человека. Бытовые
занятия, игровые роли, внешность и отношения подходят наравне. Положительные
образы могут быть короткими, без обязательного третьего дополнения.

Игровые статусы (порядочность, рейтинг, бан, калибровка, траст, скины) остаются.
Хвосты про предметы, варды, телепорты, сборки и тактические действия убраны:
они описывают матч и часто плохо сочетаются с персонажем. Убраны также
интернет, периферия и анкетные фразы. «С пингом 5» сохранено как принятый пример.

Формулировка «с большими бубсами» хранится среди особенностей и ставится после
типажа. Числа по-прежнему выбираются независимо и не исправляются под текст.


Бытовые типажи и грубые характеристики используются наравне с игровыми:
пикми, кочка, колхозница, тусовщица и другие. Название ранга в словаре — «титан».
Окраска положительных выпадений сохраняется; они не получают отрицательные
особенности из общего словаря.

Для особенности с самостоятельной фразой задаётся `joiner: comma`: генератор
добавляет запятую перед фразой. По умолчанию используется пробел. Пунктуация
не создаёт дополнительный смысловой элемент: лимит по-прежнему 1–3.


Редакторская правка может ограничивать конкретное сочетание без удаления слов.
У прилагательных и особенностей `avoid_archetypes` содержит ID типажей, с которыми
их не соединяют. Эти ограничения сохраняются при ослаблении антиповторов.
Загрузчик проверяет ссылки и наличие совместимых, в том числе положительных,
вариантов для каждого типажа.

`standalone: false` у типажа означает, что ему нужно прилагательное или особенность.
Если весь доступный набор состоит из таких типажей, короткая выдача получает
прилагательное. «Умная» и «накачанная» остаются в словаре; исключены только
отмеченные неудачные пары. «Йогиня» остаётся с дополнительной характеристикой.
