## Активность сообщений/голоса и Wrapped (`cogs/user_stats.py`)

Отдельный от игровой активности модуль: считает **количество сообщений** и
**«умное» голосовое время**, а поверх собирает красивые wrapped-карточки
(месячные/годовые серверные и персональные годовые в ЛС). Картинки рендерятся
через matplotlib.

| Команда | Описание |
|---------|----------|
| `/wrapped [user] [year]` | (Админ) Персональный итог года картинкой (по умолчанию — ваш, текущий год) |
| `/topstats [period]` | (Админ) Серверные итоги активности картинкой. `period`: `month` (по умолчанию) или `year` |
| `/wrapped_optout` | (Админ) Включить/выключить персональную рассылку wrapped в ЛС |
| `/wrapped_monthly <year> <month>` | (Админ) Опубликовать месячный серверный wrapped в канал отчётов |
| `/wrapped_yearly <year>` | (Админ) Опубликовать годовой серверный wrapped в канал отчётов |

**Как считается голос (умно).** Время идёт в зачёт, только пока пользователь
реально активен: он не в AFK-канале, не заглушён на приём (`deaf`/`self_deaf`),
и в канале есть как минимум `min_humans_in_channel` живых участников. Мут
микрофона по умолчанию **засчитывается** (человек слушает) — управляется
`count_while_muted`. Точное «говорит/молчит» по gateway недоступно, поэтому
ориентируемся на voice-state.

**Сообщения** считаются по событию `on_message` (боты, ЛС и команды
игнорируются), без анти-спам кулдауна — учитывается каждое сообщение.

**Автоматические посты** (канал `channels.activity_reports`, время — по МСК):

- Месячный серверный wrapped — 1-го числа за прошлый месяц в 12:02 МСК (после отчётов
  по играм в 12:00 и реакциям в 12:01 — посты идут в канал в этом порядке);
- Годовой серверный wrapped — `schedule.yearly_day`/`yearly_month` (по умолчанию 31 декабря);
- Персональная рассылка в ЛС — `schedule.personal_day`/`personal_month` (по умолчанию 25 декабря),
  только активным участникам и с учётом `/wrapped_optout`; закрытые ЛС пропускаются.

Дневные данные хранятся в `daily_user_stats`, в полночь по МСК переносятся в
`monthly_user_stats` (как у игровой активности). Отказы от рассылки — в
`wrapped_opt_outs`.

### Настройка

```yaml
user_stats:
  count_while_muted: true     # Засчитывать время с выключенным микрофоном
  min_humans_in_channel: 2    # Минимум живых участников в канале для зачёта
  voice_min_record: 60        # Минимальная длительность сегмента для записи (сек)
  voice_max_record: 86400     # Верхний порог сегмента (защита от аномалий, сек)
  voice_periodic_save: 300    # Интервал периодического сохранения голоса (сек)
  top_limit: 5                # Сколько позиций в топах wrapped
  dm_send_delay: 0.5          # Задержка между ЛС при рассылке (сек)
  data_since: "2026-06-01"    # Дата старта сбора (для сноски в годовом wrapped)
  schedule:
    hour: 12                  # Время wrapped-постов (МСК)
    minute: 0
    yearly_month: 12
    yearly_day: 31
    personal_month: 12
    personal_day: 25
    personal_enabled: true
```

## Аниме (`cogs/anime.py`)

| Команда | Описание |
|---------|----------|
| `/post_anime [rating] [tag]` | (Админ) Ручная публикация. `rating` (`g`/`s`/`q`/`e`) и `tag` опциональны и переопределяют конфиг |

Автоматическая публикация дважды в день (10:00 и 18:00 UTC) из **Danbooru**.
В каждом посте гарантированно есть девочка (`base_tags`), рейтинг выбирается случайно из
`ratings` (g/s). Из-за лимита Danbooru (Member — 2 «обычных» тега) используются две стратегии:

- **франшиза** (с вероятностью `extra_tag_chance`): `<франшиза> order:random rating:X score:>=N`
  — истинный рандом; наличие девочки проверяется ботом по тегам поста;
- **базовый тег**: `<1girl|2girls> order:rank rating:X` — «горячее» (ранг = качество),
  надёжно даже на тяжёлом теге.

В канал постится сама картинка (ссылка), детали (художник, источник, score) идут в лог.

Настройка в `config/bot_settings.yaml`:

```yaml
anime:
  min_score: 50            # score:>=N для франшиза-запроса (фильтр качества)
  extra_tag_chance: 0.6    # вероятность уйти в франшиза-запрос вместо базового
  ratings: ["g", "s"]      # случайный рейтинг на каждый запрос
  base_tags: ["1girl", "2girls"]
  extra_tags: ["genshin_impact", "persona", "danganronpa"]
  excluded_tags: ["guro", "comic", "monochrome"]
```

Аутентификация Danbooru (опционально) — через `.env`: `DANBOORU_LOGIN` и `DANBOORU_API_KEY`.
Ключ даёт только повышенный rate-limit; лимит в 2 тега привязан к уровню аккаунта (Member),
а не к ключу, и модуль это уже учитывает.

### Команда Quote

Цитаты хранятся как изображения в `assets/quotes/<username>/`. Добавление:

1. Создайте папку в `assets/quotes/` с именем пользователя
2. Добавьте изображения (`.jpg`, `.jpeg`, `.png`, `.gif`, `.webp`)
3. Пользователь автоматически появится в автокомплите

Либо через **контекст-меню** (ПКМ по сообщению с картинкой → «В цитаты»):
картинка-вложение сохраняется в папку автора сообщения (имя файла — id
сообщения, поэтому повторное добавление не плодит дубли), и сразу доступна в
`/quote <автор>`.

## CS2 / FACEIT (`cogs/cs_lastmatch.py`, `cogs/cs_links.py`)

Данные берутся из [FACEIT Data API](https://developers.faceit.com) — нужен `FACEIT_API_KEY` в `.env`. Покрываются матчи FACEIT (официальный матчмейкинг Valve публичного API не имеет).

| Команда | Описание |
|---------|----------|
| `/cslink <ник>` | Привязка аккаунта FACEIT по нику (до 5 аккаунтов) |
| `/csunlink [ник]` | Отвязка аккаунта FACEIT (без аргумента — все) |
| `/cslinks` | Список привязанных аккаунтов FACEIT |
| `/cslastmatch [member]` | Информация о последнем матче CS2 (PNG-карточка: Rating, K/D/A, K/D, ADR, HS, MVP, K/R, Entry, Clutch, Utility, счёт, recent-форма) |

Карточка CS2 рисуется тем же модулем `utils/match_card/` (квадрат 1080×1080): фон — сплеш
карты из `utils/match_card/assets/maps/<карта>.jpg` (если файла нет — procedural-фон),
круглый аватар FACEIT (или буква-заглушка), число-якорь Rating, плитки W/L по последним
матчам и сетка статов 3×3. Лейблы английские, вердикт-комментарий — русский.
Advanced-статы (Entry/Clutch/Utility) показывают `—`, если FACEIT их не отдаёт.
Кнопки — FACEIT-матч и Профиль.

## Музыка (`cogs/music.py`)

Базируется на **Lavalink v4** (отдельный JVM-контейнер) и Python-клиенте **wavelink 3.x**. Подробности развёртывания см. в [Деплое](deployment.md).

| Команда | Описание |
|---------|----------|
| `/play <query>` | URL (YouTube/Spotify/Apple Music/SoundCloud/Bandcamp/Twitch/Vimeo) или текстовый поиск (по умолчанию через YouTube Music) |
| `/skip` | Пропустить текущий трек (заказчик трека или админ) |
| `/stop` | Остановить и покинуть канал (только админ) |
| `/pause` | Пауза |
| `/resume` | Возобновить |
| `/queue [page]` (`/q`) | Постраничная очередь с кнопками `◀ 🔄 ▶` |
| `/nowplaying` (`/np`) | Текущий трек с обложкой и метаданными |
| `/remove <index>` | Удалить трек из очереди (заказчик или админ) |
| `/clearqueue` (alias `cq`) | Очистить очередь (только админ) |
| `/loop <off\|track\|queue>` | Режим повтора |
| `/shuffle` | Перемешать очередь |
| `/volume <0-200>` | Громкость (только админ) |
| `/seek <MM:SS\|HH:MM:SS\|секунды>` | Перемотать текущий трек |

Все команды — гибридные: работают и как `/slash`, и с префиксом `!`.

Сообщение "Сейчас играет" содержит кнопки управления (▶/⏸, ⏭, ⏹, 🔁, 🔀, 📜). Бот автоматически покидает канал, если остаётся один или простаивает без музыки (`music.voice.inactive_timeout` секунд).

### Поддерживаемые источники

| Источник | Через | Заметки |
|----------|-------|---------|
| YouTube / YouTube Music | `youtube-source` плагин Lavalink | OAuth с burner-аккаунтом для обхода bot-detection (см. деплой) |
| Spotify | LavaSrc плагин | Метаданные через Spotify API → стрим через YouTube. Требует `SPOTIFY_CLIENT_ID/SECRET` |
| Apple Music, Deezer, Yandex Music | LavaSrc плагин | По умолчанию выключены в `lavalink/application.yml` — включить при необходимости |
| SoundCloud, Bandcamp, Twitch, Vimeo, Nico | стандартные source-ы Lavalink | Работают «из коробки» |

### Поиск по тексту

`/play Imagine Dragons Believer` → wavelink делает `ytmsearch:` запрос, возвращает топ-10. Бот показывает Select-меню — выбираете нужный трек, он встаёт в очередь.

Альтернативные префиксы (продвинутое использование, можно передать в `/play`):

- `spsearch:queen bohemian` — поиск в Spotify
- `scsearch:queen bohemian` — поиск в SoundCloud
- `ytsearch:queen bohemian` — обычный YouTube (по умолчанию используется YouTube Music)

### Права доступа

- **Админ сервера**: всё.
- **Заказчик текущего трека**: pause/resume/skip/loop/shuffle/seek/remove (только свои треки).
- **Прочие в том же VC**: nowplaying, queue.
- **Не в VC**: ничего, кроме просмотра nowplaying/queue.

### Настройка

```yaml
music:
  lavalink:
    secure: false              # https/wss для удалённой ноды за TLS-прокси
    identifier: "MAIN"
    search_limit: 10           # сколько результатов в Select-меню
    default_volume: 50         # стартовая громкость
    max_volume: 200            # верхняя граница /volume
    queue_page_size: 10        # треков на странице /queue
  voice:
    connection_timeout: 30.0
    inactive_timeout: 300      # сек простоя до автодисконнекта
```

Host/port/password Lavalink-ноды берутся из `.env`: `LAVALINK_HOST`, `LAVALINK_PORT`, `LAVALINK_SERVER_PASSWORD`.

## Сбор пати (`cogs/party.py`)

| Команда | Описание |
|---------|----------|
| `/party [image]` | Собрать пати через пошаговый эфемерный мастер: **роль** (выпадушка) → **параметры** (модалка со свободным вводом времени, состава и комментария) → **превью** с кнопкой «Опубликовать». `image` — необязательное вложение-картинка. После публикации рассылаются DM всем участникам с выбранной ролью. |
| `/party_cancel` | Отменить свой последний активный сбор |
| `/party_block <user> [reason]` | (Админ) Запретить пользователю вызывать `/party` |
| `/party_unblock <user>` | (Админ) Снять блокировку. Параметр `user` — с автокомплитом: подсказываются только реально заблокированные (ник + причина) |
| `/party_blocklist` | (Админ) Список заблокированных |

Доступны для выбора только роли, выданные через `/role_assign` (то есть те,
что висят в канале с роль-реакциями).

Поток сбора:

0. `/party` открывает **эфемерный мастер** (виден только тебе):
   - **Шаг 1** — выпадушка со списком разрешённых ролей.
   - **Шаг 2** — кнопка ✏️ **Параметры** открывает модалку, где свободным
     текстом вводятся время (минуты), размер состава и комментарий
     (комментарий опционален). Значения валидируются по лимитам из конфига.
   - **Шаг 3** — превью готового embed-а с кнопкой 📣 **Опубликовать**
     (или 🚫 **Отмена** на любом шаге). Пока не нажата «Опубликовать»,
     рассылки нет, и кулдаун не тратится.
   Между публикациями действует кулдаун `party.command_cooldown_seconds` на
   одного юзера (тратится только при успешной публикации). Забаненные через
   `/party_block` мастер не откроют.
1. После публикации бот вешает embed в текущий канал и параллельно шлёт **DM**
   каждому, у кого есть указанная роль (кроме инициатора и заблокированных).
   В DM — тот же embed, что висит в канале, плюс две кнопки: ✅ **Готов** и
   ❌ **Не готов**. Если передана картинка — она показывается в embed.
2. Любое нажатие кнопки обновляет embed синхронно во всех местах: и в канале,
   и во всех личках. Между нажатиями действует кулдаун
   `party.button_cooldown_seconds` секунд на одного юзера (по умолчанию 60),
   чтобы нельзя было спамить туда-сюда.
3. **Готов** добавляет юзера в список готовых: первые `count` человек
   (инициатор + ещё `count - 1` записавшихся) — в **«Готовы»**, остальные — в
   **«Начинку»**. **Не готов** переносит в отдельный список **«Не пойдут»**.
   Перенажатия двигают юзера между списками; если готовый передумал — первый
   из начинки занимает освободившееся место.
4. **Чек готовности** (если `party.enable_ready_check: true`). Как только основа
   набрана, сбор переходит в фазу чека: у каждого из основы кнопка меняется на
   🟢 **Подтверждаю** и открывается личное окно `party.confirm_window_seconds`
   секунд (по умолчанию 120). Инициатор подтверждён автоматически. Каждому из
   основы (кроме инициатора) в DM сразу прилетает **отдельное сообщение-пинг**
   `party.confirm_request_message` — потому что молчаливое обновление embed легко
   пропустить. Кто не успел подтвердить — выбывает в **«Не подтвердили»**, его
   слот занимает первый из начинки (резерва), которому в DM прилетает нудж
   `party.confirm_nudge_message`. Начинка во время чека продолжает набираться.
   Как только весь состав подтверждён — сбор закрывается досрочно.
5. По истечении `when` минут (или сразу после полного подтверждения) бот пишет в
   исходный канал отдельное сообщение с пингами **подтвердивших** (шаблон
   `party.finished_message_template`), снимает кнопки во всех DM и помечает embed
   закрытым. Если после чека состав собрался лишь частично — используется
   `party.partial_finished_message` (пинг только подтвердивших). Если состав не
   набран — `empty_finished_message`, который теперь тоже пингует тех, кто всё же
   был готов (`{ready_pings}`).

Инициатор автоматически в списке готовых/подтвердивших (с эмодзи
`party.initiator_emoji`, по умолчанию `👑`) и DM ему не отправляется. Несколько
активных пати на сервере — разрешены, у каждого свой embed и свой набор
DM-сообщений.

Кулдаун команды — `party.command_cooldown_seconds` секунд на одного
пользователя (по умолчанию 1 час).

### Настройка

```yaml
party:
  initiator_emoji: "👑"           # Эмодзи рядом с инициатором
  min_duration_minutes: 1
  max_duration_minutes: 240       # 4 часа
  min_count: 1
  max_count: 25
  command_cooldown_seconds: 3600  # 1 час между вызовами /party на одного юзера
  button_cooldown_seconds: 60     # Кулдаун между нажатиями кнопок «Готов» / «Не готов»
  dm_send_delay: 0.1              # Между отправкой DM, чтобы не упереться в rate-limit
  finished_message_template: "Пати собрано! {ready_pings} — кто не пришёл, тот пидарас. ({role}: {comment})"
  empty_finished_message: "Не набрали состав на {role} ({comment}). Были готовы: {ready_pings}"
  enable_ready_check: true           # Чек готовности после заполнения основы
  confirm_window_seconds: 120        # Окно на «Подтверждаю» для каждого участника
  ready_check_poll_seconds: 1.0      # Период опроса дедлайнов подтверждения
  confirm_request_message: "🔔 Состав собрался! Жми «Подтверждаю», что реди — иначе слот уйдёт запасному."
  confirm_nudge_message: "🔔 Освободилось место в основе — жми «Подтверждаю», пока не уплыло!"
  partial_finished_message: "Пати собрано частично: {ready_pings} ({role}: {comment})."
```

Blacklist хранится в таблице `party_blocks` (Tortoise ORM), управляется
исключительно через слэш-команды. Активные пати живут в памяти и не
переживают перезапуск бота — после рестарта кнопки в DM перестанут работать
(юзер увидит ephemeral «сбор уже закрыт»).

## Роли по кнопкам (`cogs/role_reaction.py`)

Выдача ролей через **persistent-кнопки** под ролевым сообщением (раньше было на
эмодзи-реакциях). Нажатие кнопки переключает роль: есть — снимаем, нет — выдаём.
Кнопки реализованы через `discord.ui.DynamicItem` (`role_id` зашит в `custom_id`),
поэтому переживают рестарт бота. Параметр `emoji` теперь задаёт значок на кнопке.

| Команда | Описание |
|---------|----------|
| `/setup_role_message` | (Админ) Создать ролевое сообщение |
| `/role_assign <role> <emoji> <description>` | (Админ) Добавить роль-кнопку |
| `/role_remove <emoji>` | (Админ) Удалить роль-кнопку |

## Топ реакций (`cogs/top_reactions.py`)

| Команда | Описание |
|---------|----------|
| `/topreactions [month] [year] [all_time]` | (Админ, тест-режим) Топ сообщений по уникальным реакторам |
| `/topauthors [month] [year] [all_time]` | (Админ, тест-режим) Топ авторов по сумме реакций на их сообщения |

Команды сейчас в тест-режиме и доступны только администраторам сервера — пока
обкатываем live-трекинг и обработку исторических данных. После стабилизации
ограничение будет снято.

### Общие параметры периода

- **`month`** (1–12) и **`year`** — задают конкретный диапазон:
    - оба не указаны → текущий месяц;
    - только `month` → этот месяц текущего года;
    - только `year` → весь указанный год;
    - оба указаны → конкретный месяц и год (можно смотреть прошлые периоды).
- **`all_time`** — `True` показывает топ за всё время и игнорирует `month` / `year`.

Примеры:

- `/topreactions` — топ сообщений за текущий месяц;
- `/topreactions month:11 year:2025` — топ сообщений за ноябрь 2025;
- `/topreactions year:2025` — топ сообщений за весь 2025-й;
- `/topauthors all_time:True` — топ авторов за всё время.

`/topauthors` агрегирует уникальных реакторов по всем сообщениям автора и
показывает их сумму плюс количество сообщений, попавших в эту сумму. То есть
автор с тремя сообщениями на 3 / 4 / 5 уникальных реакторов получит
`12 реакций за 3 сообщ.`.

### Автоматический ежемесячный отчёт

1-го числа каждого месяца в **12:00 МСК** (то же время, что и ежемесячный отчёт
ActivityTracker) бот публикует в канал `channels.activity_reports` топ сообщений
за прошедший месяц. Если за месяц не было сообщений с реакциями — отчёт не
отправляется. Размер топа управляется тем же `top_reactions.live_top`.

Бот слушает события `on_raw_reaction_*` и поддерживает в БД таблицы:

- `reacted_messages` — метаданные сообщений с реакциями
- `message_reactors` — записи `(message_id, user_id, emoji)` для подсчёта уникальных реакторов

При первой реакции на ранее неизвестное боту сообщение выполняется ленивая
подгрузка: бот фетчит сообщение и все его реакции, чтобы счётчик отражал
реальное состояние. Это позволяет корректно работать со старыми сообщениями,
на которые ставят реакции через лидерборд.

### Настройка

```yaml
top_reactions:
  live_top: 10               # Сколько позиций в обычной выдаче и автоотчёте
  all_time_top: 50           # Сколько позиций в режиме all_time
  per_page: 10               # Позиций на одной странице (пагинация кнопками)
  content_preview_length: 200
  preview_inline_length: 80  # Лимит превью текста в одной строке embed
  view_timeout: 300
  ignored_message_ids: []    # Ручной чёрный список сообщений
  ignore_role_reaction_message: true   # Игнорировать сообщение role-реакций
  ignore_self_reactions: true  # Не считать реакции автора на своё сообщение
  ignore_bots: true            # Не учитывать ботов (авторов и реакторов)
```

Боты (по `ignore_bots`) не попадают ни в `/topreactions`, ни в `/topauthors`:
их сообщения не показываются, а их реакции не идут в счётчик. Список ботов
берётся из участников гилда на момент выдачи.
