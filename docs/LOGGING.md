# Система логирования PD Bot

В этом документе описана система логирования, используемая в проекте PD Bot, включая ее архитектуру, настройку и рекомендации по использованию.

## 1. Архитектура системы логирования

### 1.1 Общая структура

Система логирования PD Bot построена на стандартном модуле `logging` Python с расширениями для:
- Форматирования логов в JSON для удобного анализа
- Цветного вывода в консоль
- Контекстного логирования
- Пересылки логов в Discord-канал в реальном времени

### 1.2 Ключевые компоненты

- **utils/logging_utils.py**: Основной модуль с утилитами для расширенного логирования
  - `setup_logging()`: Настройка системы логирования
  - `JsonFormatter`: Класс для форматирования логов в JSON
  - `with_context()`: Декоратор для добавления контекста к логам

- **cogs/logging_cog.py**: Ког для пересылки логов в Discord-канал
  - Отправляет весь текущий лог при запуске бота
  - Отслеживает новые записи в файле логов (аналог `tail -f`)
  - Форматирует JSON-логи для удобного чтения в Discord

### 1.3 Иерархия логгеров

Для обеспечения единообразия и удобства фильтрации используется иерархическая структура имен логгеров:

- **Корневой логгер**: `"bot"` — для общих модулей
- **Подсистемы**: `"bot.cogs"`, `"bot.utils"`, `"bot.handlers"` и т.д.
- **Конкретные модули**: `"bot.cogs.music"`, `"bot.utils.dota_api"` и т.д.
- **Подмодули**: `"bot.utils.music.player"`, `"bot.utils.music.ui"` и т.д.

## 2. Настройка логирования

### 2.1 Инициализация в main.py

Логирование настраивается в `main.py` с использованием функции `setup_logging()`:

```python
from utils.logging_utils import setup_logging

# Настройка расширенного логирования
log_path = setup_logging(
    log_dir="logs",
    log_level=logging.INFO,
    enable_json_logs=True,
    enable_console_logs=True,
)

# Получаем логгер для текущего модуля
logger = logging.getLogger("bot.main")
```

### 2.2 Параметры настройки

Функция `setup_logging()` принимает следующие параметры:

- `log_dir`: Директория для хранения логов (по умолчанию: "logs")
- `log_level`: Уровень логирования (по умолчанию: `logging.INFO`)
- `enable_json_logs`: Включить JSON-форматирование логов (по умолчанию: `True`)
- `enable_console_logs`: Включить вывод в консоль (по умолчанию: `True`)

### 2.3 Файлы логов

- Каждый запуск бота создает новый файл лога в директории `logs/` с именем в формате `YYYY-MM-DD_HH-MM-SS.log`
- Создается симлинк `logs/latest.log`, указывающий на последний файл лога
- Логи сохраняются в формате JSON для удобного анализа

## 3. Использование логгеров

### 3.1 Создание логгера

В каждом модуле следует создавать логгер с иерархическим именем:

```python
import logging

# Для кога
logger = logging.getLogger("bot.cogs.music")

# Для утилиты
logger = logging.getLogger("bot.utils.dota_api")

# Для подмодуля
logger = logging.getLogger("bot.utils.music.player")
```

### 3.2 Уровни логирования

Используйте соответствующие уровни логирования:

- `logger.debug()`: Детальная отладочная информация
- `logger.info()`: Подтверждение, что все работает как ожидается
- `logger.warning()`: Индикация потенциальных проблем
- `logger.error()`: Ошибки, которые не препятствуют работе программы
- `logger.critical()`: Критические ошибки, которые могут привести к остановке программы

### 3.3 Примеры использования

```python
# Простое логирование
logger.info("Бот запущен")
logger.warning("Внимание: что-то пошло не так")

# Логирование с исключением
try:
    # Какой-то код
except Exception as e:
    logger.error(f"Произошла ошибка: {e}", exc_info=True)

# Логирование с дополнительными данными
logger.info("Получена команда", extra={"command": "play", "user_id": 123456789})
```

### 3.4 Контекстное логирование

Для добавления контекста к группе логов используйте декоратор `with_context()`:

```python
from utils.logging_utils import with_context

@with_context(logger, {"user_id": 123456789, "guild_id": 987654321})
async def process_command():
    logger.info("Начало обработки команды")
    # Код обработки команды
    logger.info("Команда обработана")
```

## 4. Пересылка логов в Discord

### 4.1 Настройка канала

ID канала для пересылки логов задается в `data/config.json` ключом `LOGGING_CHANNEL_ID`. Если ключ отсутствует, используется значение по умолчанию.

```json
{
  "LOGGING_CHANNEL_ID": 1365045098785542224
}
```

### 4.2 Формат логов в Discord

Логи в Discord отправляются в виде блоков кода с форматированием:
- Временная метка
- Уровень логирования
- Имя логгера (последняя часть)
- Сообщение
- Контекст (если есть)
- Информация об исключении (если есть)

## 5. Рекомендации и лучшие практики

### 5.1 Именование логгеров

- Всегда используйте иерархические имена логгеров, начинающиеся с `"bot"`
- Для когов используйте `"bot.cogs.имя_кога"`
- Для утилит используйте `"bot.utils.имя_утилиты"`
- Для подмодулей используйте `"bot.имя_модуля.имя_подмодуля"`

### 5.2 Уровни логирования

- `DEBUG`: Используйте для детальной информации, полезной при отладке
- `INFO`: Используйте для подтверждения, что все работает как ожидается
- `WARNING`: Используйте для индикации потенциальных проблем
- `ERROR`: Используйте для ошибок, которые не препятствуют работе программы
- `CRITICAL`: Используйте для критических ошибок, которые могут привести к остановке программы

### 5.3 Содержание сообщений

- Сообщения должны быть информативными и содержать контекст
- Избегайте слишком длинных сообщений
- Для сложных данных используйте JSON-форматирование или структурированный вывод
- При логировании исключений всегда включайте информацию о стеке вызовов (`exc_info=True`)


## 6. Отладка и анализ логов

### 6.1 Просмотр логов в файле

Логи сохраняются в директории `logs/` в формате JSON. Для просмотра последнего лога можно использовать:

```bash
cat logs/latest.log
```

### 6.2 Фильтрация логов

Для фильтрации логов по уровню или модулю можно использовать стандартные инструменты командной строки:

```bash
# Фильтрация по уровню
grep '"level": "ERROR"' logs/latest.log

# Фильтрация по модулю
grep '"logger": "bot.cogs.music"' logs/latest.log

# Фильтрация по сообщению
grep 'Ошибка при выполнении команды' logs/latest.log
```

### 6.3 Просмотр логов в Discord

Логи автоматически пересылаются в указанный Discord-канал, что позволяет отслеживать состояние бота в реальном времени без доступа к серверу.

## 7. Заключение

Система логирования PD Bot предоставляет мощные инструменты для отладки и мониторинга работы бота. Правильное использование логгеров и уровней логирования позволяет быстро находить и устранять проблемы, а также отслеживать состояние бота в реальном времени.

При разработке новых модулей или изменении существующих всегда следуйте установленным правилам именования и использования логгеров для обеспечения единообразия и удобства анализа логов.
