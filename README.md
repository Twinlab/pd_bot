# PD Bot

## 1. Обзор проекта

PD Bot - это многофункциональный Discord бот, разработанный на Python с использованием библиотеки discord.py. Бот предоставляет широкий спектр возможностей, включая:

*   Интеграцию с Dota 2 API для отображения статистики матчей
*   Музыкальный плеер с поддержкой YouTube
*   Развлекательные команды и симуляцию битв между пользователями
*   Систему розыгрышей с автоматическим выбором победителя
*   Административные инструменты для модерации сервера
*   Отслеживание игровой активности пользователей
*   Систему ролей по реакциям для автоматической выдачи ролей

Бот использует гибридные команды, поддерживающие как традиционный префиксный синтаксис (`!команда`), так и Discord slash-команды (`/команда`).

## 3. Технические особенности

*   **Загрузка конфигурации (`config.py`, `main.py`):**
    *   Основная конфигурация (`BOT_TOKEN`, `STRATZ_API_KEY`, `PREFIX` и др.) загружается из `data/config.json` функцией `load_config()`.
    *   Привязки аккаунтов Dota 2 и статистика активности хранятся в базе данных SQLite `data/bot_data.db`. Управление данными осуществляется через `utils/links_data_manager.py` и `utils/activity_data_manager.py`.
    *   Загруженная конфигурация (`config`) прикрепляется к объекту `bot` в `main.py` (`bot.config`), делая ее доступной для всех когов.
*   **Инициализация БД (`main.py`, `utils/database.py`):**
    *   При запуске бота функция `initialize_database()` проверяет/создает файл `data/bot_data.db` и необходимые таблицы (`links`, `daily_activity`, `monthly_activity`, `role_reactions`).
*   **Загрузка модулей (`main.py`):**
    *   Функция `load_cogs()` динамически сканирует директорию `cogs/` и загружает все `.py` файлы (кроме `__init__.py`) как расширения (коги).
    *   Обработчики событий (`handlers.events`) и сообщений (`handlers.message_handler`) загружаются явно.
*   **Обработка ошибок (`utils/error_handler.py`):**
    *   Декоратор `@command_error_handler` используется для всех команд для унифицированного перехвата и логирования исключений.
    *   Функции `safe_send()` и `safe_send_error()` обеспечивают отправку сообщений пользователю с учетом типа команды (slash или префиксная) и состояния взаимодействия.
*   **Взаимодействие с API Dota 2 (`utils/dota_api.py`, `dota_match_utils.py`):**
    *   Используется API Stratz через GraphQL-запросы.
    *   Реализовано кэширование ответов API (матчи, предметы) в памяти (с TTL) и на диске (`data/cache/`) для снижения нагрузки и ускорения ответов.
    *   Используется механизм повторных запросов (`query_api_with_retry`) при ошибках API.
*   **Музыкальный плеер (`cogs/music.py`, `utils/music/`):**
    *   Полностью переработан с использованием современных подходов `discord.py`.
    *   Использует `yt-dlp` для поиска (YouTube) и скачивания аудио (предпочтительный кодек - Opus).
    *   Воспроизведение осуществляется через `discord.FFmpegPCMAudio`.
    *   Модульная структура в директории `utils/music/`:
        *   `player.py`: Класс `MusicPlayer` для управления воспроизведением и очередью
        *   `ui.py`: Интерактивные компоненты UI (кнопки, выпадающие списки)
        *   `embeds.py`: Создание эмбедов для музыкальных команд
        *   `yt_integration.py`: Функции для работы с YouTube (поиск, скачивание)
        *   `config.py`: Конфигурация музыкального модуля (логгер, опции FFmpeg)
    *   Ког `MusicCog` (`cogs/music.py`) управляет единственным экземпляром `MusicPlayer` (т.к. бот рассчитан на один сервер).
    *   Реализованы интерактивные компоненты (`discord.ui`):
        *   Результаты поиска команды `/play` отображаются в виде выпадающего списка (`Select`).
        *   Под сообщением "Сейчас играет" отображаются кнопки управления (`Buttons`: Пауза/Возобновить, Пропустить, Стоп, Очередь).
    *   Скачанные аудиофайлы временно хранятся в `downloads/` и автоматически удаляются после воспроизведения или при полной остановке плеера.
    *   Реализовано логирование действий плеера через настроенный логгер в `config.py`.
*   **Отслеживание активности (`cogs/activity.py`):**
    *   Статистика активности хранится в базе данных SQLite (`data/bot_data.db`) в таблицах `daily_activity` и `monthly_activity`.
    *   Активность отслеживается через событие `on_presence_update` в коге `ActivityTracker`.
    *   Данные о завершенных или текущих сессиях записываются в таблицу `daily_activity` через `ActivityDataManager`.
    *   Фоновая задача `periodic_save` вызывает обновление текущих сессий для записи в БД.
    *   Фоновая задача `daily_report` (в 00:00 МСК) отправляет отчет за прошедший день (на основе `daily_activity`), затем переносит данные из `daily_activity` в `monthly_activity` и очищает `daily_activity` за прошедший день.
    *   Ежедневные и ежемесячные отчеты генерируются фоновыми задачами (`daily_report`, `monthly_report`).
    *   Используется ID канала для отчетов из `config.json` (`REPORT_CHANNEL_ID`), если он указан, иначе используется значение по умолчанию.
*   **Механизм обновления (`cogs/update.py`):**
    *   Команда `/update` выполняет `git pull` и запускает скрипт `restart.sh`.
    *   Скрипт `restart.sh` использует `sudo systemctl restart discord-bot` для перезапуска.
    *   **Зависимости:** Требует `git`, `systemd` и настройки `sudo` без пароля для пользователя бота на команду `systemctl restart discord-bot`.

Бот инициализируется в `main.py`, который загружает конфигурацию из `data/config.json`, прикрепляет ее к объекту бота, настраивает логирование и запускает все коги и обработчики.

## 3. Установка и запуск

### 3.1 Требования

*   Python 3.8+
*   Зависимости из `requirements.txt`
*   FFmpeg (для музыкального плеера)

### 3.2 Установка зависимостей

```bash
pip install -r requirements.txt
```

### 3.3 Настройка конфигурации

Создайте файл `data/config.json` со следующим содержимым (замените значения-заполнители):

```json
{
  "BOT_TOKEN": "ваш-токен-discord-бота",
  "STRATZ_API_KEY": "ваш-токен-stratz-api",
  "PREFIX": "!",
  "PROXY_URL": "",
  "REPORT_CHANNEL_ID": 573665353327181824,
  "ANIME_CHANNEL_ID": 298811309640646666
}
```
*   `BOT_TOKEN`: Токен вашего Discord бота.
*   `STRATZ_API_KEY`: Ключ API Stratz (для Dota 2).
*   `PREFIX`: Префикс для текстовых команд (например, "!"). Бот загружает этот префикс при запуске. Если ключ отсутствует, используется "!" по умолчанию.
*   `PROXY_URL`: URL прокси-сервера для yt-dlp (опционально).
*   `REPORT_CHANNEL_ID`: ID канала для отчетов активности. Бот использует это значение для отправки ежедневных и ежемесячных отчетов. Если ключ отсутствует, используется значение по умолчанию `573665353327181824`.
*   `ANIME_CHANNEL_ID`: ID текстового канала для автоматической публикации аниме-изображений.

**ВАЖНО:** Не добавляйте файлы `data/config.json` и `data/bot_data.db` в систему контроля версий (Git). Убедитесь, что `data/` добавлен в `.gitignore`.

### 3.4 Запуск бота

```bash
python main.py
```

Для непрерывной работы рекомендуется использовать менеджер процессов, такой как `systemd` или `supervisor` (см. раздел 4.7 для команды `update`).

## 4. Модули (Cogs) и Команды

### 4.1 Административный (`cogs/admin.py`)

*   `/clear [count] [user]`: Удаление сообщений (до 100, обходит 14-дневный лимит).
*   `/kick <member> [reason]`: Исключение пользователя с сервера.
*   `/restart`: (Только для владельца) Перезапуск бота через systemd. Требует настройки `sudo` без пароля для пользователя бота на команду `systemctl restart discord-bot` (имя сервиса по умолчанию `discord-bot`).

### 4.2 Аниме (`cogs/anime.py`)

*   Автоматически публикует случайные SFW аниме-изображения в канал, указанный в `ANIME_CHANNEL_ID`, дважды в день (10:00 и 18:00 UTC).
*   `/post_anime`: (Только для администраторов) Ручной запуск публикации аниме-изображения.

### 4.3 Отслеживание Активности (`cogs/activity.py`)

*   `/activity [test_mode]`: Показывает текущую дневную статистику (только для администраторов). Использует интерактивное представление с пагинацией и переключением режимов (пользователи/игры).
*   `/mystats [user] [month] [year]`: Показывает статистику пользователя за указанный месяц (или текущий) с пагинацией.
*   `/mystatsall [user]`: Показывает статистику пользователя за всё время (из текущего месяца и архивов) с пагинацией.
*   **Автоматические отчеты:** Ежедневный и ежемесячный отчеты отправляются в жестко заданный канал (ID `573665353327181824` в `cogs/activity.py`).
*   **Хранение данных:**
    *   `data/bot_data.db`: База данных SQLite, содержащая таблицы `daily_activity` (статистика за текущий день) и `monthly_activity` (агрегированная статистика по месяцам).

### 4.4 Развлечения (`cogs/fun.py`)

*   `/deathbattle [member1] [member2]`: Симуляция битвы.
*   `/snipe`: Показ последнего удаленного сообщения в канале (кэш в памяти, сбрасывается при перезапуске).
*   `/penis [user]`: Измерение "пениса".
*   `/avatar [user]`: Отображение аватара.

### 4.5 Розыгрыши (`cogs/giveaway.py`)

*   `/giveaway <duration> <description>`: Создание розыгрыша.
*   **Примечание:** Текущая реализация не сохраняет активные розыгрыши при перезапуске бота.

### 4.6 Dota 2 Интеграция (`cogs/lastmatch.py`, `cogs/links.py`)

*   `/link <player_id>`: Привязка Steam ID Dota 2 к Discord аккаунту (до 5 аккаунтов). Данные хранятся в `data/bot_data.db`.
*   `/unlink [player_id]`: Отвязка Steam ID (если ID не указан, отвязываются все).
*   `/links`: Показ привязанных аккаунтов.
*   `/lastmatch [member]`: Отображение детальной информации о последнем матче Dota 2 (автоматически выбирается аккаунт с последней игрой). Использует API Stratz.

### 4.7 Музыка (`cogs/music.py`, `utils/music/`)

Модуль полностью переписан для повышения стабильности и добавления интерактивности. Используются slash-команды и компоненты `discord.ui`. Логика разделена на модули в директории `utils/music/`.

*   `/play <query>`: Воспроизведение музыки по URL (YouTube, SoundCloud и др. поддерживаемые `yt-dlp`) или поисковому запросу на YouTube. При поиске отображает интерактивный список результатов для выбора.
*   `/skip`: Пропускает текущий трек. Может быть вызван через slash-команду или кнопку под плеером.
*   `/stop`: Полностью останавливает воспроизведение, очищает очередь, удаляет временные файлы и отключает бота от голосового канала. Может быть вызван через slash-команду или кнопку.
*   `/pause`: Ставит воспроизведение на паузу. Может быть вызван через slash-команду или кнопку.
*   `/resume`: Возобновляет воспроизведение после паузы. Может быть вызван через slash-команду или кнопку.
*   `/queue`: Показывает текущий трек и очередь воспроизведения (как эфемерное сообщение). Может быть вызван через slash-команду или кнопку.
*   `/volume <0-200>`: Устанавливает громкость воспроизведения в процентах.
*   **Интерактивное управление:** Сообщение "Сейчас играет" содержит кнопки для быстрого доступа к `pause`/`resume`, `skip`, `stop`, `queue`.
*   **Модульная архитектура:**
    * `player.py`: Класс `MusicPlayer` для управления воспроизведением и очередью
    * `ui.py`: Интерактивные компоненты UI (кнопки, выпадающие списки)
    * `embeds.py`: Создание эмбедов для музыкальных команд
    * `yt_integration.py`: Функции для работы с YouTube (поиск, скачивание)
    * `config.py`: Конфигурация музыкального модуля (логгер, опции FFmpeg)
*   **Автоотключение:** Бот автоматически покидает голосовой канал, если остается в нем один (логика реализована в `on_voice_state_update` внутри `handlers/events.py`).

### 4.8 Обновление (`cogs/update.py`)

*   `/update`: (Только для владельца бота) Получает последние изменения из Git (`git pull`) и перезапускает бота с помощью скрипта `restart.sh`.
*   **Требования:** Бот должен быть запущен как сервис `systemd` с именем `discord-bot` (или другим, указанным в скрипте). Пользователь бота должен иметь права на перезапуск этого сервиса через `sudo` без пароля.
*   **ВНИМАНИЕ:** Использование `sudo` в скрипте несет риски безопасности.

### 4.9 Роли по реакциям (`cogs/role_reaction.py`)

*   `/setup_role_message [channel_id]`: (Только для администраторов) Создает сообщение для получения ролей через реакции. Если указан ID канала, сообщение будет создано в этом канале, иначе - в текущем. По умолчанию используется канал с ID 1366858138153910282.
*   `/role_assign <role> <emoji> <description>`: (Только для администраторов) Добавляет роль, которую можно получить через реакцию. Требуется указать роль, эмодзи и описание роли.
*   `/role_remove <emoji>`: (Только для администраторов) Удаляет роль из списка ролей, получаемых через реакции.
*   **Автоматическая выдача ролей:** Пользователи получают роли при нажатии на соответствующие эмодзи и теряют их при удалении реакций.
*   **Хранение данных:** Привязки ролей к эмодзи хранятся в базе данных SQLite (`data/bot_data.db`) в таблице `role_reactions`.

### 4.10 Логирование (`cogs/logging_cog.py`)

*   Этот ког не предоставляет команд пользователю.
*   Он автоматически отслеживает файл `bot.log` и пересылает новые строки в заданный Discord канал.
*   **Примечание:** ID канала для логирования в настоящее время жестко задан в коде (`cogs/logging_cog.py`). В будущем его следует вынести в конфигурационный файл `data/config.json`.

## 5. Обработка ошибок (`utils/error_handler.py`)

*   Используется декоратор `@command_error_handler` для унифицированной обработки ошибок в большинстве команд.
*   Стандартные ошибки (недостаточно прав, неверный аргумент и т.д.) обрабатываются автоматически.
*   Необработанные ошибки логируются.
*   Функция `safe_send_error` используется для отправки сообщений об ошибках пользователю (учитывая slash-команды).

## 6. Кэширование (`utils/dota_api.py`)

*   **API Dota 2:** Результаты запросов к API Stratz кэшируются в памяти (с TTL) и на диске (`data/cache/`) для уменьшения нагрузки на API.
*   **Привязки аккаунтов:** Хранятся в базе данных SQLite (`data/bot_data.db`).
*   **Статистика активности:** Хранится в базе данных SQLite (`data/bot_data.db`).
*   **Snipe:** Удаленные сообщения кэшируются в памяти (`utils/snipe_utils.py`).

## 7. Логирование: Единый стандарт

В проекте используется централизованная иерархическая система логирования, обеспечивающая единообразие во всех модулях.

### 7.1 Конфигурация логирования

Логирование настраивается в `main.py` с помощью `logging.basicConfig`:

```python
import logging

logging.basicConfig(
    level=logging.INFO,
    format='%(asctime)s - %(name)s - %(levelname)s - %(message)s',
    handlers=[
        logging.FileHandler("bot.log"),
        logging.StreamHandler()
    ]
)
logger = logging.getLogger("bot")
```

- Все логи пишутся в файл `bot.log` и выводятся в консоль.
- Формат логов: время, имя логгера, уровень, сообщение.

### 7.2 Именование логгеров

Для единообразия используйте иерархические имена логгеров:

- **Основной логгер:** `"bot"` — для общих модулей, когов, обработчиков.
- **Подсистемы:** `"bot.music"`, `"bot.dota"`, `"bot.database"`, `"bot.links_db"`, `"bot.activity_db"` и т.д.
- **Dota-модули:** используйте `"bot.dota"` вместо `"dota_bot"` (требуется обновить в `utils/dota_utils.py`, `utils/dota_match_utils.py`, `utils/dota_api.py`).
- **Музыкальный модуль:** используйте `"bot.music"` во всех музыкальных файлах (включая `cogs/music.py`).

**Пример инициализации логгера:**
```python
import logging
logger = logging.getLogger("bot.music")  # для музыкального модуля
```

### 7.3 Использование логгера в подмодулях

Для подмодулей рекомендуется импортировать логгер из главного модуля подсистемы:

```python
# utils/music/player.py
from .config import logger  # logger = logging.getLogger("bot.music") в config.py
```

Это обеспечивает единый источник логгирования для всей подсистемы.

### 7.4 Пример использования

```python
logger.info("Бот запущен")
logger.warning("Внимание: что-то пошло не так")
logger.error("Ошибка при выполнении команды", exc_info=True)
```

### 7.5 Пересылка логов в Discord

- Все новые записи из `bot.log` автоматически пересылаются в специальный Discord-канал через ког `cogs/logging_cog.py`.
- ID канала для логирования задается в коде (см. комментарии в `cogs/logging_cog.py`).

### 7.6 Требования к новым модулям

- Всегда определяйте логгер в начале файла с правильным иерархическим именем.
- Для подмодулей используйте импорт логгера из главного модуля подсистемы.
- Не используйте print для отладки — только логгер.

**Пример для нового модуля:**
```python
import logging
logger = logging.getLogger("bot.subsystem")
```
## 8. Расширение функциональности

Для добавления новых команд:

1.  Создайте новый файл кога в директории `cogs/` (например, `cogs/my_cog.py`).
2.  Напишите класс, наследующий `commands.Cog`.
3.  Добавьте методы команд с декораторами `@commands.hybrid_command()` и `@command_error_handler`.
4.  Добавьте асинхронную функцию `setup(bot)` в конце файла для регистрации кога.
5.  Бот автоматически загрузит новый ког при следующем запуске.
