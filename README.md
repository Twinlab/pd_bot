# PD Bot

## 1. Обзор проекта

PD Bot - это многофункциональный Discord бот, разработанный на Python с использованием библиотеки discord.py. Бот предоставляет широкий спектр возможностей, включая:

*   Интеграцию с Dota 2 API для отображения статистики матчей
*   Музыкальный плеер с поддержкой YouTube
*   Развлекательные команды и симуляцию битв между пользователями
*   Административные инструменты для модерации сервера
*   Отслеживание игровой активности пользователей
*   Систему ролей по реакциям для автоматической выдачи ролей

Бот использует гибридные команды, поддерживающие как традиционный префиксный синтаксис (`!команда`), так и Discord slash-команды (`/команда`).

## 3. Технические особенности

*   **Система конфигурации (`config/`, `main.py`):**
    *   Используется современная система на основе Pydantic Settings + YAML файлов.
    *   Секретные данные (`BOT_TOKEN`, `STRATZ_API_KEY` и др.) загружаются из `.env` файла.
    *   Основные настройки загружаются из `config/bot_settings.yaml` с автоматической валидацией типов.
    *   Функция `get_settings()` из `config/` предоставляет доступ к настройкам с IDE поддержкой.
    *   Доступ к настройкам осуществляется через объект `bot.settings`.
    *   Привязки аккаунтов Dota 2 и статистика активности хранятся в базе данных SQLite `data/bot_data.db`. Управление данными осуществляется через `utils/links_data_manager.py` и `utils/activity_data_manager.py`.
*   **Инициализация БД (`main.py`, `utils/database.py`):**
    *   Используется **Tortoise ORM** для работы с базой данных.
    *   При запуске бота функция `initialize_database()` инициализирует ORM и генерирует схемы таблиц, если они отсутствуют.
    *   Модели данных определены в `utils/models.py`.
*   **Загрузка модулей (`main.py`):**
    *   Функция `load_cogs()` динамически сканирует директорию `cogs/` и загружает все `.py` файлы (кроме `__init__.py`) как расширения (коги).
    *   Обработчики событий (`handlers.events`) и сообщений (`handlers.message_handler`) загружаются явно.
*   **Обработка ошибок (`utils/error_handler.py`):**
    *   Декоратор `@command_error_handler` используется для всех команд для унифицированного перехвата и логирования исключений.
    *   Функции `safe_send()` и `safe_send_error()` обеспечивают отправку сообщений пользователю с учетом типа команды (slash или префиксная) и состояния взаимодействия.
*   **Взаимодействие с API Dota 2 (`utils/dota_api.py`, `dota_match_utils.py`):**
    *   Используется API Stratz через GraphQL-запросы.
    *   Реализовано кэширование ответов API (матчи, предметы) в памяти (с TTL) и на диске (`data/cache/`) для снижения нагрузки и ускорения ответов.
    *   Используется механизм повторных запросов (`query_api_with_retry`) при ошибках API.
*   **Музыкальный плеер (`cogs/music.py`, `utils/music/`):**
    *   Полностью переработан с использованием современных подходов `discord.py`.
    *   Использует `yt-dlp` для поиска на YouTube и получения прямых ссылок на аудиопотоки.
    *   Воспроизведение осуществляется в потоковом режиме через `discord.FFmpegPCMAudio`, без скачивания файлов на диск.
    *   Модульная структура в директории `utils/music/`:
        *   `player.py`: Класс `MusicPlayer` для управления воспроизведением и очередью
        *   `ui.py`: Интерактивные компоненты UI (кнопки, выпадающие списки)
        *   `embeds.py`: Создание эмбедов для музыкальных команд
        *   `yt_integration.py`: Функции для работы с YouTube (поиск, получение информации о потоках)
        *   `config.py`: Конфигурация музыкального модуля (логгер, опции FFmpeg)
    *   Ког `MusicCog` (`cogs/music.py`) управляет единственным экземпляром `MusicPlayer` (т.к. бот рассчитан на один сервер).
    *   Реализованы интерактивные компоненты (`discord.ui`):
        *   Результаты поиска команды `/play` отображаются в виде выпадающего списка (`Select`).
        *   Под сообщением "Сейчас играет" отображаются кнопки управления (`Buttons`: Пауза/Возобновить, Пропустить, Стоп, Очередь).
    *   Реализовано логирование действий плеера через настроенный логгер в `config.py`.
*   **Отслеживание активности (`cogs/activity.py`, `utils/activity/`):**
    *   `cogs/activity.py`: Содержит основной класс кога `ActivityTracker`, команды, обработчики событий Discord и запуск фоновых задач.
    *   `utils/activity_data_manager.py`: Управляет взаимодействием с таблицами `daily_activity` и `monthly_activity` в `data/bot_data.db`.
    *   `utils/activity/views.py`: Содержит классы `discord.ui.View` (`ActivityView`, `StatsView`) для интерактивных отчетов и статистики.
    *   `utils/activity/reports.py`: Содержит основную логику генерации и отправки ежедневных/ежемесячных отчетов, вызываемую фоновыми задачами и командами ручного запуска.
    *   `utils/activity/helpers.py`: Вспомогательные функции (форматирование времени, проверка ботов).
   *   Активность отслеживается через `on_presence_update` в коге `ActivityTracker`.
   *   Данные о текущих сессиях хранятся в памяти кога и периодически (`periodic_save`) или при завершении сессии записываются в `daily_activity` через `ActivityDataManager`.
   *   Фоновая задача `daily_report` (в 00:00 МСК) вызывает логику из `utils/activity/reports.py`, которая отправляет отчет за вчерашний день, а затем вызывает `ActivityDataManager` для переноса данных `daily -> monthly` и очистки `daily`.
   *   Фоновая задача `monthly_report` (в 12:00 МСК 1-го числа) вызывает логику из `utils/activity/reports.py` для отправки отчета за предыдущий месяц.
   *   ID канала для отчетов настраивается в `config/bot_settings.yaml`.
*   **Механизм обновления (`cogs/update.py`):**
   *   Команда `/update` выполняет `git pull` и инициирует перезапуск бота.
   *   **Требования:** Для автоматического перезапуска в `config/bot_settings.yaml` должна быть указана команда в секции `update.restart_command`. Например: `restart_command: "systemctl --user restart discord-bot.service"`. Если команда не указана, бот просто завершит работу, и его нужно будет перезапустить вручную или с помощью внешнего скрипта.

Бот инициализируется в `main.py`, который загружает конфигурацию, настраивает логирование и запускает все коги и обработчики.

## 3. Установка и запуск

### Конфигурация проекта

Проект использует `pyproject.toml` для централизованной конфигурации инструментов разработки:

- **ruff**: Единый инструмент для линтинга и форматирования кода (заменяет black, isort, flake8)
- **mypy**: Проверка типов с настройками для различных модулей
- **pytest**: Конфигурация для тестирования (asyncio_mode, filterwarnings)

Все настройки инструментов находятся в `pyproject.toml`, что упрощает поддержку и обеспечивает согласованность.

### 3.1 Требования

*   Docker
*   Docker Compose

### 3.2 Настройка конфигурации

Бот использует современную систему конфигурации на основе Pydantic Settings + YAML файлов.

#### Файлы конфигурации

- **`.env`** - секретные данные (токены, API ключи)
- **`config/bot_settings.yaml`** - основные настройки

#### Настройка

1. **Скопируйте `.env.example` в `.env`:**
```bash
cp .env.example .env
```

2. **Заполните обязательные поля в `.env`:**
   - `BOT_TOKEN`: Токен вашего Discord бота
   - `STRATZ_API_KEY`: API ключ для Dota 2 (Stratz)
   - `TWITCH_CLIENT_ID` и `TWITCH_CLIENT_SECRET`: (Опционально) Для Twitch уведомлений

3. **При необходимости отредактируйте `config/bot_settings.yaml`:**
   - Настройте ID каналов, таймауты и другие параметры.

**ВАЖНО:** Не добавляйте файлы `.env` и `data/bot_data.db` в систему контроля версий (Git). Убедитесь, что они добавлены в `.gitignore`.

### 3.3 Запуск бота (Docker)

Рекомендуемый способ запуска — через Docker Compose. Это обеспечивает изолированное окружение и автоматический перезапуск.

1. **Сборка и запуск:**
```bash
docker compose up -d --build
```

2. **Просмотр логов:**
```bash
docker compose logs -f
```

3. **Остановка:**
```bash
docker compose down
```

### 3.4 Обновление

Для обновления кода бота:

1. **Через Discord:** Используйте команду `/update` (только для владельца). Бот скачает обновления и перезапустится.
2. **Вручную:**
```bash
git pull
docker compose restart bot
```
Если изменились зависимости (библиотеки), используйте `docker compose up -d --build`.

## 6. Модули (Cogs) и Команды

### 6.1 Административный (`cogs/admin.py`)

*   `/clear [count] [user]`: Удаление сообщений (до 100, обходит 14-дневный лимит).

### 6.2 Аниме (`cogs/anime.py`)

Модуль автоматически публикует случайные SFW аниме-изображения с safebooru.org в настроенный канал дважды в день (10:00 и 18:00 UTC).

*   **Источник изображений**: API safebooru.org
*   **Настройка тегов**: Все теги настраиваются в `config/bot_settings.yaml` в секции `anime`
*   **Обязательный тег**: Тег `1girl` всегда добавляется во все запросы
*   **Fallback система**: Если основной запрос не дает результатов, выполняется запрос только с `1girl` + исключения
*   **Поддержка исключений**: Теги-исключения добавляются с префиксом `-` для фильтрации нежелательного контента
*   **Кеширование**: Модуль ведет кеш опубликованных изображений в БД (таблица `anime_cache`) для предотвращения повторов
*   `/post_anime`: (Только для администраторов) Ручной запуск публикации аниме-изображения

#### Настройка в bot_settings.yaml:

```yaml
anime:
  # Теги для поиска (можно использовать ЛЮБЫЕ теги с safebooru.org)
  tags:
    - "anime"
    - "1girl"
    - "cute"
    - "kawaii"
    # ... добавляй любые теги: neko, catgirl, fox_ears, maid, etc.

  # Теги для исключения (добавляются с префиксом -)
  excluded_tags:
    - "nude"
    - "nsfw"
    - "explicit"
    # ... добавляй теги для исключения

  max_tags_per_request: 6  # Лимит тегов за запрос
  rating: "safe"           # Рейтинг изображений (safe/questionable/explicit)
```

**Важно**: В YAML можно использовать любые теги, существующие на safebooru.org. Теги в `settings.py` - только значения по умолчанию.

### 6.3 Отслеживание активности (`cogs/activity.py`, `utils/activity/`)

Модуль отслеживает игровую активность пользователей и предоставляет статистику. Логика разделена между когом и вспомогательными утилитами.

*   `/activity [test_mode]`: (Админ) Показывает текущую дневную статистику. Использует интерактивное представление (`ActivityView`) с пагинацией и переключением режимов (пользователи/игры).
*   `/mystats [user] [month] [year]`: Показывает статистику пользователя за указанный месяц (или текущий). Использует интерактивное представление (`StatsView`) с пагинацией.
*   `/mystatsall [user]`: Показывает статистику пользователя за всё время. Использует интерактивное представление (`StatsView`) с пагинацией.
*   `/report_daily <year> <month> <day>`: (Админ) Вручную отправляет ежедневный отчет за указанную дату в канал отчетов. **Не выполняет перенос данных.**
*   `/report_monthly <year> <month>`: (Админ) Вручную отправляет ежемесячный отчет за указанный месяц и год в канал отчетов.
*   **Автоматические отчеты:**
    *   Ежедневный отчет (за вчера) отправляется в 00:00 МСК. После отправки данные переносятся из дневной в месячную статистику.
    *   Ежемесячный отчет (за прошлый месяц) отправляется 1-го числа в 12:00 МСК.
    *   Канал для отчетов определяется `REPORT_CHANNEL_ID` в `config.json`.
*   **Хранение данных:**
    *   `data/bot_data.db`: База данных SQLite, таблицы `daily_activity` и `monthly_activity`. Управляется через `utils/activity_data_manager.py`.
*   **Конфигурация:** Пороги минимального/максимального времени записи сессии и минимального времени для ежемесячного отчета настраиваются в `data/config.json` (см. раздел 3.3).
*   **Вспомогательные модули:**
    *   `utils/activity/views.py`: Интерактивные представления.
    *   `utils/activity/reports.py`: Логика генерации и отправки отчетов.
    *   `utils/activity/helpers.py`: Форматирование времени и др.

#### 6.4.1 Команда Quote (`utils/quotes_utils.py`)

Модуль для отправки случайных цитат пользователей. Каждая папка в `assets/quotes/` представляет пользователя с его цитатами.

**Использование:**
*   `/quote` - Отправляет случайную цитату любого пользователя
*   `/quote <user>` - Отправляет случайную цитату указанного пользователя

**Особенности:**
*   **Автокомплит**: При вводе имени пользователя показываются доступные варианты
*   **Простота использования**: Пользователи не знают о структуре папок
*   **Поддержка форматов**: `.jpg`, `.jpeg`, `.png`, `.gif`, `.webp`
*   **Автоматическое сканирование**: Пользователи сканируются динамически при каждом запросе
*   **Валидация**: Проверка существования пользователей и наличия цитат

**Структура папок:**
```
assets/quotes/
├── odji/           # Цитаты пользователя odji
│   ├── 1.jpg
│   ├── 2.png
│   └── ...
├── fineser/        # Цитаты пользователя fineser
│   └── 1.png
└── qustic/         # Цитаты пользователя qustic
    └── 1.png
```

**Настройка в bot_settings.yaml:**
```yaml
fun:
  quotes:
    assets_path: "assets/quotes"
    supported_extensions:
      - ".jpg"
      - ".jpeg"
      - ".png"
      - ".gif"
      - ".webp"
    view_timeout: 300  # Таймаут для UI компонентов (секунды)
    max_folders_in_select: 25  # Максимум пользователей в автокомплите
```

**Добавление новых цитат:**
1. Создайте папку в `assets/quotes/` с именем пользователя
2. Добавьте изображения цитат в поддерживаемых форматах
3. Пользователь автоматически появится в автокомплите при следующем использовании


### 6.6 Dota 2 Интеграция (`cogs/lastmatch.py`, `cogs/links.py`)

*   `/link <player_id>`: Привязка Steam ID Dota 2 к Discord аккаунту (до 5 аккаунтов). Данные хранятся в `data/bot_data.db`.
*   `/unlink [player_id]`: Отвязка Steam ID (если ID не указан, отвязываются все).
*   `/links`: Показ привязанных аккаунтов.
*   `/lastmatch [member]`: Отображение детальной информации о последнем матче Dota 2 (автоматически выбирается аккаунт с последней игрой). Использует API Stratz.

### 6.7 Музыка (`cogs/music.py`, `utils/music/`)

Модуль полностью переписан для повышения стабильности и добавления интерактивности. Используются slash-команды и компоненты `discord.ui`. Логика разделена на модули в директории `utils/music/`.

*   `/play <query>`: Воспроизведение музыки по URL (YouTube, SoundCloud и др. поддерживаемые `yt-dlp`) или поисковому запросу на YouTube. При поиске отображает интерактивный список результатов для выбора.
*   `/skip`: Пропускает текущий трек. Может быть вызван через slash-команду или кнопку под плеером.
*   `/stop`: Полностью останавливает воспроизведение, очищает очередь и отключает бота от голосового канала. Может быть вызван через slash-команду или кнопку.
*   `/pause`: Ставит воспроизведение на паузу. Может быть вызван через slash-команду или кнопку.
*   `/resume`: Возобновляет воспроизведение после паузы. Может быть вызван через slash-команду или кнопку.
*   `/queue`: Показывает текущий трек и очередь воспроизведения (как эфемерное сообщение). Может быть вызван через slash-команду или кнопку.
*   `/volume <0-200>`: Устанавливает громкость воспроизведения в процентах.
*   **Интерактивное управление:** Сообщение "Сейчас играет" содержит кнопки для быстрого доступа к `pause`/`resume`, `skip`, `stop`, `queue`.
*   **Модульная архитектура:**
    * `player.py`: Класс `MusicPlayer` для управления воспроизведением и очередью
    * `ui.py`: Интерактивные компоненты UI (кнопки, выпадающие списки)
    * `embeds.py`: Создание эмбедов для музыкальных команд
    * `yt_integration.py`: Функции для работы с YouTube (поиск, получение информации о потоках)
    * `config.py`: Конфигурация музыкального модуля (логгер, опции FFmpeg)
*   **Автоотключение:** Бот автоматически покидает голосовой канал, если остается в нем один (логика реализована в `on_voice_state_update` внутри `handlers/events.py`).

### 6.8 Обновление (`cogs/update.py`)

*   `/update`: (Только для владельца бота) Получает последние изменения из Git (`git pull`) и перезапускает бота.
*   **Требования:** Для автоматического перезапуска в `config/bot_settings.yaml` должна быть указана команда в секции `update.restart_command`. Если команда не указана, бот просто завершит работу.

### 6.9 Роли по реакциям (`cogs/role_reaction.py`)

*   `/setup_role_message`: (Только для администраторов) Создает сообщение для получения ролей через реакции. Канал для сообщения определяется в `config/bot_settings.yaml`, или используется текущий канал, если ключ не задан.
*   `/role_assign <role> <emoji> <description>`: (Только для администраторов) Добавляет роль, которую можно получить через реакцию. Требуется указать роль, эмодзи и описание роли.
*   `/role_remove <emoji>`: (Только для администраторов) Удаляет роль из списка ролей, получаемых через реакции.
*   **Автоматическая выдача ролей:** Пользователи получают роли при нажатии на соответствующие эмодзи и теряют их при удалении реакций.
*   **Хранение данных:** Привязки ролей к эмодзи хранятся в базе данных SQLite (`data/bot_data.db`) в таблице `role_reactions`.

### 6.10 Логирование (`cogs/logging_cog.py`)

*   Этот ког не предоставляет команд пользователю.
*   При каждом запуске бота отправляет весь текущий лог-файл (создаётся в папке `logs/` с уникальным именем) в заданный Discord канал, а затем автоматически пересылает все новые строки, которые появляются в этом файле (реализация tail -f).
*   **Примечание:** ID канала для логирования задается в `config/bot_settings.yaml`.

## 7. Обработка ошибок (`utils/error_handler.py`)

*   Используется декоратор `@command_error_handler` для унифицированной обработки ошибок в большинстве команд.
*   Стандартные ошибки (недостаточно прав, неверный аргумент и т.д.) обрабатываются автоматически.
*   Необработанные ошибки логируются.
*   Функция `safe_send_error` используется для отправки сообщений об ошибках пользователю (учитывая slash-команды).

## 8. Кэширование (`utils/dota_api.py`)

*   **API Dota 2:** Результаты запросов к API Stratz кэшируются в памяти (с TTL) и на диске (`data/cache/`) для уменьшения нагрузки на API.
*   **Привязки аккаунтов:** Хранятся в базе данных SQLite (`data/bot_data.db`).
*   **Статистика активности:** Хранится в базе данных SQLite (`data/bot_data.db`).
*   **Snipe:** Удаленные сообщения кэшируются в памяти (`utils/snipe_utils.py`).

## 9. Логирование: Единый стандарт

В проекте используется централизованная иерархическая система логирования, обеспечивающая единообразие во всех модулях.

### 9.1 Конфигурация логирования

Логирование настраивается в `main.py` с использованием расширенной системы логирования из `utils/logging_utils.py`:

```python
import logging
from utils.logging_utils import setup_logging

# Настройка расширенного логирования
log_path = setup_logging(
    log_dir="logs",
    log_level=logging.INFO,
    enable_json_logs=True,
    enable_console_logs=True,
)

# Получаем логгер для текущего модуля
logger = logging.getLogger("bot.main")
```

- Все логи пишутся в отдельный файл в папке `logs/` для каждого запуска бота (например, `logs/2025-04-30_01-16-00.log`) и выводятся в консоль.
- Поддерживается JSON-форматирование логов для удобного анализа.
- Цветное логирование в консоли для лучшей читаемости.
- Автоматическое создание симлинка на последний лог-файл.

### 9.2 Именование логгеров

Для единообразия используйте иерархические имена логгеров:

- **Основной логгер:** `"bot"` — для общих модулей, когов, обработчиков.
- **Подсистемы:** `"bot.music"`, `"bot.dota"`, `"bot.database"`, `"bot.links_db"`, `"bot.activity_db"` и т.д.
- **Dota-модули:** используйте `"bot.dota"` вместо `"dota_bot"` (требуется обновить в `utils/dota_utils.py`, `utils/dota_match_utils.py`, `utils/dota_api.py`).
- **Музыкальный модуль:** используйте `"bot.music"` во всех музыкальных файлах (включая `cogs/music.py`).

**Пример инициализации логгера:**
```python
import logging
logger = logging.getLogger("bot.music")  # для музыкального модуля
```

### 9.3 Использование логгера в подмодулях

Для подмодулей рекомендуется импортировать логгер из главного модуля подсистемы:

```python
# utils/music/player.py
from .config import logger  # logger = logging.getLogger("bot.music") в config.py
```

Это обеспечивает единый источник логгирования для всей подсистемы.

### 9.4 Пример использования

```python
logger.info("Бот запущен")
logger.warning("Внимание: что-то пошло не так")
logger.error("Ошибка при выполнении команды", exc_info=True)
```

### 9.5 Пересылка логов в Discord

- При каждом запуске бота весь текущий лог-файл (из папки `logs/`) автоматически отправляется в специальный Discord-канал через ког `cogs/logging_cog.py`.
- После этого все новые строки, появляющиеся в этом файле, также автоматически пересылаются в этот канал (реализация tail -f).
- ID канала для логирования задается в `config/bot_settings.yaml`.

### 9.6 Требования к новым модулям

- Всегда определяйте логгер в начале файла с правильным иерархическим именем.
- Для подмодулей используйте импорт логгера из главного модуля подсистемы.
- Не используйте print для отладки — только логгер.

**Пример для нового модуля:**
```python
import logging
logger = logging.getLogger("bot.subsystem")
```

### 9.7 Расширенные возможности логирования

Модуль `utils/logging_utils.py` предоставляет дополнительные возможности для логирования:

- **JSON-форматирование логов**: Класс `JsonFormatter` для структурированного логирования в формате JSON.
- **Контекстное логирование**: Декоратор `with_context` для добавления контекстной информации к логам внутри функций.
- **Гибкая настройка**: Функция `setup_logging` с параметрами для настройки директории, уровня логирования, форматов и т.д.

Пример использования контекстного логирования:

```python
from utils.logging_utils import with_context

@with_context(logger, {"user_id": 123, "guild_id": 456})
def process_command():
    logger.info("Обработка команды")  # Лог будет содержать контекст {"user_id": 123, "guild_id": 456}
```
## 10. Отслеживание Twitch-стримов (`cogs/twitch.py`)

## 11. Расширение функциональности

Для добавления новых команд:

1.  Создайте новый файл кога в директории `cogs/` (например, `cogs/my_cog.py`).
2.  Напишите класс, наследующий `commands.Cog`.
3.  Добавьте методы команд с декораторами `@commands.hybrid_command()` и `@command_error_handler`.
4.  Добавьте асинхронную функцию `setup(bot)` в конце файла для регистрации кога.
5.  Бот автоматически загрузит новый ког при следующем запуске.
