1. Обзор проекта
PD Bot - это многофункциональный Discord бот, разработанный на Python с использованием библиотеки discord.py версии 2.3.2. Бот предоставляет широкий спектр возможностей, включая:

Интеграцию с Dota 2 API для отображения статистики матчей
Музыкальный плеер с поддержкой YouTube
Развлекательные команды и симуляцию битв между пользователями
Систему розыгрышей с автоматическим выбором победителя
Административные инструменты для модерации сервера
Бот использует гибридные команды, поддерживающие как традиционный префиксный синтаксис (!команда), так и Discord slash-команды.

2. Архитектура
Проект построен на модульной архитектуре, использующей систему когов (Cogs) discord.py для организации команд и функциональности. Основная структура приложения:

bash
pd_bot/
├── main.py                # Точка входа приложения
├── config.py              # Управление конфигурацией
├── cogs/                  # Модули команд
├── handlers/              # Обработчики событий
├── utils/                 # Вспомогательные функции
└── data/                  # Данные и кэширование
Бот инициализируется в main.py, который загружает конфигурацию, настраивает логирование и запускает все необходимые модули. Основной цикл событий управляется асинхронной библиотекой asyncio.

3. Основные компоненты
3.1 Система команд (Cogs)
Все команды бота организованы в когах - специальных классах, которые изолируют функциональность по назначению:

admin.py - Административные команды для модерации сервера
fun.py - Развлекательные команды
giveaway.py - Система розыгрышей
lastmatch.py - Команды для отображения статистики Dota 2
links.py - Управление привязками аккаунтов
music.py - Музыкальный плеер
Каждый ког регистрируется в боте при запуске через функцию load_cogs() в main.py.

3.2 Обработчики событий
Система обработки событий Discord организована в двух основных модулях:

events.py - Обрабатывает основные события Discord (запуск бота, изменения в голосовых каналах, ошибки команд)
message_handler.py - Специализируется на обработке сообщений пользователей, включая специальные реакции
3.3 Утилиты
Утилиты предоставляют специализированные функции, которые используются когами и обработчиками:

dota_api.py - Взаимодействие с API Dota 2
dota_utils.py - Вспомогательные функции для работы с данными Dota 2
dota_match_utils.py - Обработка данных о матчах
music_utils.py - Основная логика музыкального плеера
error_handler.py - Унифицированная обработка ошибок
message_utils.py - Обработка сообщений и реакций
Другие специализированные утилиты для развлекательных команд
3.4 Система хранения данных
Бот использует несколько типов хранения данных:

Конфигурационные файлы в формате JSON для настроек бота
Кэширование запросов API в файлах JSON для оптимизации производительности
Пользовательские данные (привязки аккаунтов) в JSON файлах

- По умолчанию показывает данные за текущий месяц

Команда mystatsall:
- Объединяет статистику из текущего месяца и всех архивных файлов
- Показывает все игры с пагинацией (10 игр на странице)
- Предоставляет общую статистику: количество уникальных игр и суммарное игровое время

Права на отправку сообщений и эмбедов в канал cybersport

Разные стратегии для slash-команд и обычных команд

python

import discord
from discord.ext import commands

class NewFeature(commands.Cog):
    def __init__(self, bot):
        self.bot = bot
    
    @commands.hybrid_command()

async def setup(bot):
    await bot.add_cog(NewFeature(bot))
Добавление утилит для поддержки новой функциональности:

python
# utils/new_feature_utils.py
async def process_feature_data(data):
    # Обработка данных для новой функции

Регистрация обработчиков событий (при необходимости):

python
@commands.Cog.listener()
async def on_specific_event(self, *args, **kwargs):

Бот автоматически загрузит новый ког при запуске, так как в main.py реализована функция load_cogs(), которая сканирует директорию cogs/ и загружает все найденные модули.

bash

Для обеспечения работы бота в фоновом режиме можно использовать:

Сообщение или трассировка ошибки
Для долгосрочного использования рекомендуется настроить ротацию логов, например, с помощью библиотеки logging.handlers.RotatingFileHandler.

10. Детальное описание ключевых API и структур данных
10.1 Структура конфигурации
Основной файл конфигурации config.json содержит следующие ключи:

BOT_TOKEN - Токен Discord бота
STRATZ_API_KEY - Ключ API для Stratz (Dota 2)
STEAM_API_KEY - Ключ API для Steam
ADMINS - Список ID администраторов бота
PREFIX - Префикс для команд (обычно "!")
PROXY_URL - URL прокси-сервера (опционально)
10.2 Структура user_links.json
Файл data/user_links.json хранит привязки Discord аккаунтов к Steam ID:

json
{
  "123456789012345678": [76561198123456789, 76561198987654321],
  "987654321098765432": [76561198555555555]
}
Где ключи - это Discord ID пользователей, а значения - списки привязанных Steam ID.

10.3 Кэширование API
Система кэширования API использует следующую структуру:

json
{
  "cache_key": {
    "data": {
      // Ответ API
    },
    "timestamp": 1625482390.4567
  },
  // ... другие кэшированные ответы
}
Где cache_key - уникальный ключ для запроса, data - ответ API, timestamp - время получения данных.

10.4 Музыкальный плеер
Музыкальный плеер использует класс MusicPlayer для управления очередью воспроизведения:

queue - двусторонняя очередь треков
current - текущий воспроизводимый трек
volume - громкость воспроизведения (0.0-1.0)
text_channel - текстовый канал для сообщений плеера
skip_votes - набор ID пользователей, проголосовавших за пропуск
Трек представлен словарем с ключами:

file - путь к локальному файлу
title - название трека
url - оригинальный URL
duration - длительность в секундах
thumbnail - URL миниатюры
requester - объект пользователя, запросившего трек
Другие метаданные (автор, ID и т.д.)

11. Безопасность и защита данных
11.1 Обработка токенов и ключей API
Бот загружает токены и ключи API из файла конфигурации, который не должен включаться в систему контроля версий. Для дополнительной безопасности можно:

Использовать переменные окружения вместо конфигурационного файла
Настроить шифрование конфигурационного файла
Ограничить доступ к файлу конфигурации на уровне файловой системы
11.2 Обработка пользовательских данных
Бот хранит минимально необходимые данные о пользователях:

Discord ID и привязанные Steam ID
Временные данные для функциональности (розыгрыши, музыка)
Все хранимые данные могут быть удалены по запросу пользователя с помощью команды !unlink.

11.3 Проверки прав доступа
Административные команды (!clear, !kick) защищены проверками прав доступа:

Команда !clear требует право administrator
Команда !kick требует право kick_members
Система проверки иерархии ролей не позволяет модераторам воздействовать на пользователей с более высокой ролью
